Exam System Design

Real-time proctored exam system with lobby/timed start, browser activity monitoring, camera permission controls, and answer auto-save.

Current Project Status

Already Implemented

  • Done Proctoring DB schema (participants, violations, drafts).
  • Done Exam model fields: start mode, session status, camera settings.
  • Done Exam create/update supports proctoring config.
  • Done Frontend exam page with WebSocket client skeleton.

Still Missing

  • Missing Backend WebSocket hub/room/client implementation.
  • Missing Participant/violation/draft repository + service methods.
  • Missing Join by invite code / join by exam ID endpoints.
  • Missing Proctor controls (start/end/warn/terminate).

Target Exam Flow

Created -> Waiting Lobby -> (Proctor Start OR Timed Start) -> Live Exam -> Finished
  • Participants can join using exam ID or invite code.
  • Proctor sees live participant state and violations.
  • Answers auto-save in real-time during exam.
  • No camera recording is stored in v1.

Join Route Decision (Unified)

Yes, this can be simplified into one route using query params while still supporting both join methods.

  • POST /api/v1/exams/join?exam_id={exam_id} - join directly by exam ID.
  • POST /api/v1/exams/join?code={invite_code} - join by invite code.
  • Validation rule: exactly one of exam_id or code must be provided.
  • If both or none are provided, return 400 Bad Request.

Core API / Socket Events

REST Endpoints

API Description
POST /api/v1/exams/join?exam_id=... | ?code=... Unified participant join route. Supports either direct exam ID or invite code.
GET /api/v1/exams/{exam_id}/invite Returns or generates invite code for proctor-controlled sharing.
GET /api/v1/exams/{exam_id}/participants Lists participant statuses, camera state, and violation counts for monitoring UI.
GET /api/v1/exams/{exam_id}/violations Returns violation logs for audit and proctor review.
GET /api/v1/exams/{exam_id}/draft Returns latest answer draft for reconnect recovery.
POST /api/v1/exams/{exam_id}/start Manual proctor start for lobby-mode exams.
POST /api/v1/exams/{exam_id}/end Ends the exam for all participants and finalizes evaluation flow.

WebSocket Events

Event Description
on-join-room Initial state sync sent right after socket join (status, schedule, title).
exam-starts-now Broadcast when exam transitions to live and timer begins.
exam-ends-now Broadcast when exam ends by timer or proctor action.
answer_update Participant sends incremental answer changes for real-time auto-save.
submit_exam Participant final submission trigger; server locks and evaluates answers.
violation_report Participant browser sends detected behavior violations (tab switch, blur, etc.).
camera_status Participant camera on/off state update for proctor dashboard.
start_exam / end_exam Proctor control events to start or end exam session.
warn_participant / kick_participant Proctor enforcement actions for suspicious behavior handling.

Camera Strategy (No Recording in v1)

Option Description Complexity Recommendation
Periodic Snapshots Send compressed camera snapshots every 10-30s to proctor via WebSocket. Low Recommended for v1
Live WebRTC Stream Use WebSocket signaling + peer connections for live monitoring. High Phase 2

Possible Issues and Mitigation

Issue Impact Mitigation
Concurrent room state updates Race conditions, incorrect participant status Use room-level mutex/channels and atomic state transitions.
WebSocket disconnects Lost updates / stale clients Heartbeat ping/pong, reconnect logic, and draft recovery endpoint.
Snapshot bandwidth growth High network usage with many participants Adjust interval, resize/compress images, soft limits per room.
Join authorization gaps Unauthorized users entering exam Enforce strict checks on join routes and WS handshake.
Message contract mismatch Frontend and backend not communicating Keep exact type/payload schema and version messages if needed.
Server restart during live exam Room state reset Persist critical state in DB and reconstruct room from DB on reconnect.
